# 프로그래매틱 SEO 페이지 인덱싱 품질 검수 보고서

기준 Git 체크포인트: `a7fbe1c` (working tree clean)
검수 방식: 코드(`src/app/**/page.tsx`, `src/data/*.ts`) 정독 + 프로덕션 빌드(`next build` / `next start`)로 실제 렌더링된 HTML 비교. **코드 수정, noindex/sitemap/canonical 실제 변경, 콘텐츠 삭제는 수행하지 않았습니다. 분석 및 본 보고서 작성만 진행했습니다.**

두 페이지의 "실질적으로 같은 문서인지"를 정량화하기 위해, `<main>` 내부 텍스트를 추출해 토큰 단위 LCS(최장 공통 부분열) 유사도를 측정했습니다. 100%면 완전히 동일, 대조군(전혀 다른 콘텐츠여야 하는 `/subject/math` vs `/subject/english`)이 43.4%, (`/grade/elementary` vs `/grade/middle`)이 31.8%로 나왔으므로, **이 사이트의 "진짜 다른 콘텐츠" 기준선은 대략 30~45%**로 보면 됩니다. 이 기준선보다 훨씬 높은 조합은 "지역명/학년/과목만 바뀐 사실상 동일 문서"로 판단했습니다.

### 5. `region + subject` — `/region/[province]/[city]/[subject]` (55개, 시/군/구 11 × 과목 5)

**이번 검수의 핵심 질문("지역+과목이 서로 충분히 다른 콘텐츠를 갖는가?")에 대한 답: 아니오, 대부분 그렇지 않습니다.**

55개 중 **수원(1개 시/군/구) × 수학/영어(2개 과목) = 2개만** `regionSubjectContent` 데이터로 실제 지역 맞춤 소개문+학년별 섹션을 갖고 있습니다. 나머지 **53개(96%)는 과목명만 알고 지역은 모르는 완전 범용 폴백 콘텐츠**를 사용합니다.

| 항목 | 평가 (53개 폴백 그룹 기준) |
|---|---|
| 1. title 고유성 | ✅ 고유 (지역+과목명 삽입) |
| 2. description 고유성 | ✅ 고유하지만 완전 템플릿 |
| 3. H1 고유성 | ✅ 고유 |
| 4. 본문 고유성 | 🔴 **매우 낮음** — 실측 유사도 **94.5%**(성남/수학 vs 용인/수학, 둘 다 폴백). 소개 문단·학년별 섹션(`grades.description` 그대로 재사용)·"이런 경우 상담" 체크리스트(`subject.painPoints`)·"수업 진행 5단계"(`subject.process`)·방문/화상 선택 영역·FAQ까지 **지역명이 등장하는 자리를 빼면 텍스트가 완전히 동일** |
| 5. 사실상 동일 문서 여부 | 🔴 **그렇다.** 같은 과목이면 어느 도시를 가든 본문이 사실상 하나의 문서 |
| 6. 검색 의도 명확성 | ✅ 검색 의도 자체는 명확("성남 수학과외") — 다만 콘텐츠가 그 의도(그 지역 특성)에 응답하지 못함 |

| 8. 내부링크 충분성 | 충분 (14~18개) |
| 9. canonical 충돌 가능성 | 기술적 canonical 오류는 없음(자기 자신을 가리킴). 다만 **실질적으로 동일한 콘텐츠를 가진 10개 URL이 각자 다른 canonical을 선언**하고 있어, Google의 중복 콘텐츠 알고리즘이 임의로 대표 URL을 고르고 나머지를 색인에서 밀어낼 위험이 큼(구글이 "선택하지 않은 canonical"로 처리) |
| 10. FAQ 반복 정도 | 🔴 **완전 동일** — "어떤 과목을 수업할 수 있나요? / 방문·화상 모두 가능한가요? / 초등학생도 가능한가요? / 수업료는 얼마인가요?" 4문항이 성남/수학, 용인/수학, 수원/수학, 그리고 시/도·시/군/구 페이지까지 **글자 하나 틀리지 않고 동일**함을 실제 HTML로 확인 |
| 11. FAQPage schema 반복 정도 | 🔴 매우 높음 — 위 4문항 JSON-LD가 55개 중 53개(+province 17+city 11)에서 동일 |
| 12. sitemap 포함 유지 적절성 | **53개는 부적절**(현재 상태 기준). 수원 2개는 유지 가능 |

- 나머지 53개: **C. noindex 권장** (현재 상태 기준). 실제 지역 맞춤 콘텐츠(`regionSubjectContent`)를 채우면 B→A로 전환 가능한 구조이므로, "영구히 제외"가 아니라 "콘텐츠 확보 전까지 보류"에 가깝습니다.

## 공통 이슈: FAQ / FAQPage 스키마 대량 반복

`homeFaqSlugs.slice(0, 4)`(동일한 4문항: 과목/방문·화상/초등학생/수업료)가 다음 3개 유형, 총 **83개의 서로 다른 URL**에서 완전히 동일하게 사용됩니다(직접 HTML 확인).

- `region` (province 17 + city 11) = 28개
- `region + subject` (55개, 수원 2개 포함) = 55개

`/subject/[slug]`(5개)만 `subject.faqSlugs`로 과목별 선택 로직이 있지만, 원본 FAQ 문항 풀 자체가 6개뿐이라 완전한 차별화는 아닙니다.

이는 개별 페이지의 title/description 고유성과는 무관하게, **구글이 한 사이트에서 "복사-붙여넣기"된 구조화 데이터를 대량으로 인식하게 되는 경로**이므로 sitemap 커버리지 문제와는 별개로 다뤄야 할 이슈입니다.

## 최종 요약

1. **현재 sitemap URL 수**: 331 (이번 보고서 대상 7개 유형 합계 315 + `guide` 아티클 5 + 정적 페이지 11)
2. **바로 index 권장(A) URL 예상 수**: **약 10개** (subject 5 + grade 3 + region+subject 수원 2개)
3. **보강 후 index 권장(B) URL 예상 수**: **약 34개** (region 32 + school 2)
4. **noindex 후보(C) 수**: **약 53개** (region+subject 폴백 그룹)
5. **sitemap 제외 후보(D) 수**: **약 218개** (region+grade 33 + region+grade+subject 165 + region+district+subject 20)
6. **가장 큰 SEO 리스크 5개**
   1. `region+grade+subject`(165개, 전체 sitemap의 약 50%)가 문장 1개 수준의 콘텐츠로 sitemap에 등재되어 있어, 최대 규모의 thin/duplicate content 리스크를 안고 있음.
   2. `region+subject` 55개 중 53개(96%)가 지역명만 바뀐 사실상 동일 문서 — "지역 맞춤"이라는 페이지 존재 이유 자체가 무너지는 핵심 리스크.
   3. FAQPage 구조화 데이터가 83개 서로 다른 URL에서 완전히 동일하게 반복 게시됨.
   4. `region+grade+subject`/`region+district+subject`(총 185개)가 FAQ조차 없고 자기 자신을 canonical로 선언하고 있어, 상위 페이지와 콘텐츠가 겹치는데도 각각 별도로 색인 경쟁을 시킴(크롤 예산 낭비 가능성).
   5. `school` 템플릿이 학교별 차별화 데이터 없이 이름만 바꾸는 구조라, 향후 학교 수가 늘어날수록(현재 2개 → 수십~수백 개) thin content 문제가 지금보다 훨씬 큰 규모로 재현될 구조적 위험.
7. **수정한다면 우선순위 1~5**
   1. `region+grade+subject`(165) + `region+district+subject`(20), 총 185개 → sitemap 제외(D) 최우선 적용.
   2. `region+grade`(33) → sitemap 제외(D).
   3. `region+subject` 폴백 53개 → noindex(C) 적용 후, `regionSubjectContent`에 실제 지역 맞춤 데이터를 채운 지역부터 순차적으로 index 전환(C→B→A).
   4. `region`(province/city) 및 `region+subject` 페이지들의 FAQ를 지역·과목 무관 공통 4문항 재사용에서 벗어나도록 구조 개선(지역 목록형 페이지는 FAQ 섹션 자체를 빼거나, 최소한 페이지 유형별로 다른 FAQ 조합 사용).
   5. `school` 템플릿에 실제로 확인 가능한 사실 정보(공식 학교 홈페이지 링크, 학년 구성, 소재지 등 — 시험 경향·교육열 등 추측성 정보 제외)를 추가해 B→A 전환 준비.

이번 세션에서는 위 권장사항을 **실제로 적용하지 않았습니다**. noindex 메타 태그 삽입, `sitemap.ts`에서 URL 제외, canonical 재설정, FAQ 구조 변경은 모두 사용자 승인 후 별도 작업으로 진행되어야 합니다.
